# Git — моя шпаргалка

> Здесь собраны основные команды Git, которые нужны мне для работы с репозиториями.
> Самые часто используемые команды находятся в начале, более редкие — в конце.

---

## Основной цикл работы

Обычно работа с Git выглядит примерно так:

1. Изменить файлы проекта.
2. Проверить изменения — `git status`.
3. Добавить нужные файлы — `git add`.
4. Создать коммит — `git commit`.
5. Отправить изменения на GitHub — `git push`.

### `git status`

Показывает текущее состояние репозитория:

```bash
git status
```

Использую, чтобы посмотреть:

- текущую ветку;
- какие файлы изменены;
- какие файлы ещё не отслеживаются;
- какие изменения уже подготовлены к коммиту.

> **Полезно:** `git status` можно выполнять в любой момент. Если не понимаю, что сейчас происходит с репозиторием — начинаю с него.

---

### `git add`

Добавить конкретный файл в будущий коммит:

```bash
git add README.md
```

Добавить все изменённые файлы:

```bash
git add .
```

После `git add` изменения ещё **не становятся коммитом**, а только подготавливаются к нему.

---

### `git commit`

Создать коммит:

```bash
git commit -m "описание изменений"
```

Например:

```bash
git commit -m "добавлена реализация класса Треугольник"
```

Коммит сохраняет подготовленное состояние проекта в истории Git.

---

### `git push`

Отправить локальные коммиты в удалённый репозиторий:

```bash
git push
```

При первой отправке новой ветки может понадобиться:

```bash
git push -u origin dev
```

После `-u` Git запоминает связь локальной ветки `dev` с удалённой.

---

### `git pull`

Получить последние изменения из удалённого репозитория:

```bash
git pull
```

Полезно выполнять перед началом работы, если с репозиторием работают несколько человек или он изменялся с другого компьютера.

---

## Ветки

Ветки позволяют работать над разными версиями проекта независимо друг от друга.

### Посмотреть ветки

```bash
git branch
```

Текущая ветка отмечается символом `*`.

Показать также удалённые ветки:

```bash
git branch -a
```

### Создать ветку

```bash
git branch dev
```

### Переключиться на ветку

```bash
git switch dev
```

Создать новую ветку и сразу на неё переключиться:

```bash
git switch -c dev
```

Старый вариант этой команды:

```bash
git checkout dev
```

---

## Клонирование репозитория

Скачать существующий репозиторий:

```bash
git clone <URL>
```

Например:

```bash
git clone https://github.com/user/project.git
```

Git создаст папку проекта вместе со всей историей коммитов.

---

## Просмотр истории

Полная история:

```bash
git log
```

Короткая история:

```bash
git log --oneline
```

История с отображением веток:

```bash
git log --oneline --graph --all
```

Пример:

```text
* a3c19ad добавлены тесты
* 83d01ac изменена структура проекта
* 27be411 добавлен класс Triangle
```

---

## Просмотр изменений

Посмотреть изменения, которые ещё не были добавлены через `git add`:

```bash
git diff
```

Посмотреть уже подготовленные изменения:

```bash
git diff --staged
```

---

## Отмена изменений

Отменить изменения файла, если они ещё не добавлены в коммит:

```bash
git restore main.cpp
```

⚠️ **Осторожно:** несохранённые в Git изменения этого файла будут потеряны.

Убрать файл из подготовленных к коммиту, но оставить сами изменения:

```bash
git restore --staged main.cpp
```

---

## Удалённый репозиторий

Посмотреть, к какому удалённому репозиторию подключён проект:

```bash
git remote -v
```

Обычно основной удалённый репозиторий называется `origin`.

Добавить удалённый репозиторий вручную:

```bash
git remote add origin <URL>
```

---

## Слияние веток

Переключиться на ветку, **в которую** нужно добавить изменения:

```bash
git switch main
```

Затем выполнить:

```bash
git merge dev
```

То есть команда выше добавит изменения из `dev` в `main`.

---

## `.gitignore`

Файл `.gitignore` содержит файлы и папки, которые Git не должен отслеживать.

Например для CLion:

```gitignore
.idea/
cmake-build-*/
```

Это позволяет не отправлять в репозиторий временные файлы среды разработки и результаты сборки.

## Дополнительные команды

| Команда | Для чего нужна |
|---|---|
| `git init` | Создать новый Git-репозиторий |
| `git status` | Посмотреть состояние репозитория |
| `git add .` | Подготовить все изменения |
| `git commit -m "..."` | Создать коммит |
| `git push` | Отправить коммиты |
| `git pull` | Получить изменения |
| `git branch` | Посмотреть ветки |
| `git switch <ветка>` | Переключиться на ветку |
| `git log --oneline` | Короткая история коммитов |
| `git diff` | Посмотреть изменения |
| `git remote -v` | Посмотреть удалённые репозитории |

### Удаление ветки

```bash
git branch -d branch_name
```

### Переименование текущей ветки

```bash
git branch -m new_name
```

### Показать информацию о конкретном коммите

```bash
git show <commit>
```

---

## Что чаще всего использую

```bash
git status
git add .
git commit -m "описание"
git push
```

А при работе с ветками:

```bash
git branch
git switch dev
git switch main
```

> **Главное правило:** перед `commit`, `push`, `merge` и другими важными действиями полезно сделать `git status` и проверить, где я нахожусь и какие файлы изменены.
